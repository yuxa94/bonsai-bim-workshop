# 마지막 실습 · IFC를 면적 원장으로 바꾸기

목표는 **파일 2개를 읽고, 면적의 근거를 구분하고, GUID로 다시 확인할 수 있는 Excel 원장을 만드는 것**입니다. 모델 작성 수업의 결과를 데이터로 사용하는 단계입니다. 전체 동을 학생 PC에 열지 않습니다.

## 1. 필요한 파일 받기

- [면적 실습 전체 ZIP](../area-lab.zip): 도구·입력2개·CSV·Excel·검증 결과
- [25B 한 세대 IFC](inputs/25B.ifc): 라이브러리 25B-v002, 약0.27MB
- [A32 05층 IFC](inputs/A32-05.ifc): 현재 v011의 단일층, 약5.32MB
- [면적표 예제 Excel](example-output/IFC-area-review.xlsx), [관측 원장 CSV](example-output/objects.csv), [층별 CSV](example-output/floors.csv)
- [실제 표 이미지](example-output/area-summary.png), [실습 도구 안내](../tools/README.md)

공개 저장소의 원본 파일 URL은 다음과 같습니다. 브라우저가 IFC 본문을 보여주면 링크를 다른 이름으로 저장합니다. 파일명이 `.ifc.txt`가 되지 않았는지 확인합니다.

```text
https://raw.githubusercontent.com/yuxa94/bonsai-bim-workshop/main/area-lab/inputs/25B.ifc
https://raw.githubusercontent.com/yuxa94/bonsai-bim-workshop/main/area-lab/inputs/A32-05.ifc
```

25B 원본은 `assets/apartment-types/20261019-v1/25B/model/25B.ifc` 보관본이며 현재25B 선택자가 가리키는 `output/25b.ifc`와 SHA256이 같습니다. 공개 사본은 개인 PC의 절대 경로가 적힌 DWG·BaseIFC 출처 문자열만 상대 경로로 바꿨습니다. 따라서 공개 사본의 해시는 원본과 다르며 GUID·형상은 같습니다. A32는 `output/a32-residential/v011/floors/A32-05.ifc`의 사본입니다. 예전 수업v1의v00905를 섞지 않았습니다. 자세한 원본/공개 해시는 [입력 출처](input-provenance.json)에 있습니다.

## 2. 첫 번째 프롬프트 · 25B만 계산하기

압축을 푼 폴더를 Codex 작업 폴더로 엽니다. 아래 문장을 그대로 붙여넣고, 결과 폴더 경로는 실제로 받은 안내를 사용합니다.

> 이 폴더의 tools/README.md와 area-lab/README.md를 읽어 줘. area-lab/inputs/25B.ifc만 읽기 전용으로 분석해 면적 원장을 새 결과 폴더에 만들어 줘. 전체 동 파일이나 기존 Blender 세션은 열지 마. 도구의 requirements.txt를 별도 가상환경에 설치하고 area_extract.py를 실행해 줘. 먼저 IfcSpace의 형상 유무·공간수·슬래브수·단위를 확인하고, 공간 투영면적과 슬래브 XY 합집합을 따로 보여 줘. CSV/JSON/HTML을 저장하고 원본 SHA256이 전후 같은지 검증해 줘. 공간명이나 타입명25B의 숫자를 면적으로 쓰지 마. 완료 후 결과 HTML과 CSV를 열어 줘.

검산값은 공간5개·형상5개·슬래브2개입니다. 공간5개의 모델 프로파일 합계는 **23.725600㎡**, 슬래브2개의 XY 합집합은 **30.190800㎡**입니다. 경계가 달라 두 값을 더하지 않습니다. 공간에는 발코니도 있으므로 공간 합계를 법정 전용면적이라 부르지 않습니다.

## 3. 두 번째 프롬프트 · 05층만 계산하기

> 이번에는 area-lab/inputs/A32-05.ifc 한 층만 새 결과 폴더에 계산해 줘. IfcSpace14개에 자체 형상이 있는지 먼저 확인하고, 없는 공간면적을0으로 채우지 마. 일반 IfcSlab의 실제 배치 프로파일을 사용해 층별 XY 합집합을 계산하고 LANDING과 ROOF는 분리해 줘. 등록 세대소속 슬래브는 세대 GUID별 합집합으로 집계하고 세대외 바닥과 구분해 줘. 타입 정의를 발생 개수와 함께 중복 합산하지 마. inputfile/GUID/class/storey/basis/area/unit/limitations 열이 있는 CSV와 검증 보고서를 저장하고, 기존 expected-results.json과 일치하는지 검사해 줘. 전체 동 IFC·전체 동 .blend는 필요 없어.

실제 검산값은 다음과 같습니다. 반올림 전 수치를 합계에 사용합니다.

| 관측값 | A32 05층 |
|---|---:|
| IfcElement 발생 개수 / 제외한 타입 정의 | 925 / 925 |
| IfcSpace / 형상 있는 공간 | 14 / 0 |
| IfcSlab 전체 / 일반 바닥 / 계단참 | 54 / 50 / 4 |
| 일반 바닥 XY 합집합 | 994.531800㎡ |
| 14세대 소속 일반 바닥 합계 | 749.514185㎡ |
| 세대외 일반 바닥 | 245.017615㎡ |
| 계단참 XY 합집합, 일반 바닥과 별도 | 11.448000㎡ |

세대소속 바닥과 세대외 바닥의 합계가 일반 바닥과 일치합니다. 세대외 바닥에는 벽·코어·미등록 용도가 섞여 있으므로 법정 공용면적으로 명명하지 않습니다. 이 예제에서 층별 바닥의 중첩은 수치 오차 수준이며, 도구는 다른 입력의 실제 중첩도 합집합으로 공제합니다.

## 4. 세 번째 프롬프트 · CSV에서 Excel 만들기

> 방금 생성한 objects.csv·floors.csv·unit-slabs.csv를 사용해 새 면적 검토.xlsx를 만들어 줘. spreadsheets 스킬로 실제 파일을 저작하고 수식 재계산과 렌더 검토까지 해 줘. 면적 요약, 관측 원장, 세대소속 슬래브 근거를 연결해 줘. 클래스가 다른 공간·슬래브는 합계에 섞지 말고 IfcSpace 형상 없음은 공란 또는 n.a.로 표시해 줘. storey05와 GUID는 텍스트로 유지해 줘. source-dimensions.json의 A32 25형 원본 치수는 별도 시트에서 폭×높이 수식으로 보여 주고, standalone25B나 IFC 면적으로 바꾸지 마. 법정 전용/공용/연면적은 미확정으로 명시해 줘. 원본 IFC·CSV를 수정하지 마.

예제 Excel은 실제2개 IFC에서 추출한75행(슬래브56+공간19)과 A32 세대14행을 포함합니다. 원본 치수 시트는 A17-001/PDF31의 **A32 25형**7구획을 옮겼으며, 합계20.203400㎡는 도면 치수 원장의 참고값입니다. 원본 PDF의 전용 표기·슬래브 모델·단독25B는 경계와 대상이 달라 같은 값으로 간주하지 않습니다.

## 5. Blender로 GUID 확인하기

선택 활동입니다. 면적 계산 자체는 Blender를 켤 필요가 없습니다. 별도 새 창에서 `25B.ifc` 또는 `A32-05.ifc` 한 파일을 Bonsai로 엽니다. 학생이 작업 중인 다른 창은 유지합니다. 전체 동은 열지 않습니다.

> 현재 Blender/Bonsai에서 열린 IFC의 저장 경로를 먼저 확인해 줘. 내가 내려받은 A32-05.ifc와 같을 때만 진행해. 면적 원장의 GUID 한 개를 선택해서 부재 이름·층·IFC 클래스·소속 공간을 보여 줘. 다른 모델 세션은 조작하지 마. 모델이나 표시 메시를 수정·저장하지 말고 선택으로만 확인해. 파일이 다르면 어떤 경로가 열렸는지 알려 주고 계산에 사용한 경로와 비교해 줘.

CSV의 미세 슬래브 조각이 화면에서 크게 보이는 경우가 있어 표시 메시의 외곽을 면적으로 쓰지 않습니다. 원본 유효 압출 단면과 GUID를 확인합니다. 이 도구는 수직 다각형 압출만 지원하며 미지원 형상은 중단합니다.

## 제출과 점검

원본 IFC2개, 새 결과 폴더의 `areas.json`, `objects.csv`, `floors.csv`, `unit-slabs.csv`, `review.html`, 새 Excel을 제출합니다. 원본 IFC는 그대로 보관합니다. Excel은 파일 안의 수식 예제이며 IFC 실시간 연결은 아닙니다. 설계가 바뀌면 같은 절차로 새 폴더에 재계산합니다.

합격 기준은 숫자 복사가 아니라 ① 입력 파일과 해시를 추적하고 ② 공간 형상 누락을 발견하고 ③ 타입 정의를 제외하며 ④ 서로 다른 면적 기준을 분리하고 ⑤ 합계와 GUID 근거를 검증하는 것입니다. [자동검사 결과](verification.json)에 실행 환경과 검산 증거가 있습니다.
